# Перенос мастерской из старой программы

Утилита читает базу старой программы и раскладывает её по файлам, которые
понимает раздел **Настройки → Базы**. Ничего никуда не отправляет и в нашу
базу не пишет.

## Как пользоваться

1. Положить рядом с `perenos.js` файлы старой программы: базу `.sqlite`
   (`.db`) и, если есть, выгрузки таблицы заказов в `.csv`.
2. Запустить `perenos.bat` двойным щелчком (или `node perenos.js`).
3. Открыть появившуюся папку `dlya-zagruzki` и загрузить файлы в программе:

   | файл | куда |
   |---|---|
   | `klienty.csv` | Настройки → Базы → Клиенты и их техника |
   | `zakazy.csv` | Настройки → Базы → Заказы |
   | `sklad.csv` | Настройки → Базы → Склад |

   Сначала клиентов, потом заказы. Наоборот тоже сработает, но тогда карточки
   заведутся по телефону из заказа — без адреса, примечаний и списка техники.

Рядом появятся `otchet.txt` (что и куда ушло) и, если что-то не поехало,
`ne-pereneseno.csv` — построчно с причиной.

Загрузка в программе идёт в два шага: сперва предпросмотр со списком ошибок,
и только потом запись. Пустая ячейка ничего не затирает, ничего не удаляется,
повторная загрузка того же файла обновляет, а не задваивает — сливаем по
телефону клиента и номеру заказа.

## Что переносится и во что

**Клиенты** — из таблицы `ClientsMap`. Номер клиента старой программы
переносится как есть и становится номером клиента у нас: по нему повторная
загрузка того же файла обновляет карточки, а не заводит вторые. Имя из капса
приводится к обычному виду, телефон — к `+7…`. Второй номер через запятую
едет в «Ещё телефон».
Галочка чёрного списка становится строкой в примечании: у нас такого признака
нет, а терять его жалко. Техника собирается из заказов этого клиента:
отдельной таблицы техники в старой программе нет.

**Заказы** — из таблицы `Catalog`. Суммы: «затраты» старой программы — это
запчасти, работы считаются как «итог минус запчасти» (отдельной строкой они
там не хранились). Гарантия «30 дней» превращается в дату — тридцать дней от
выдачи. Внешний вид, комплектность и цвет складываются в примечание приёмщика,
«выполнение работы» — в диагноз. Статусы переводятся в наши:

| в старой программе | у нас |
|---|---|
| Выдан | Выдан |
| Готов | Готов |
| Принят в работу, Согласовано | В работе |
| Диагностика | Диагностика |
| Согласование с клиентом | Ожидает согласования |
| Ждёт запчасть | Ожидание запчасти |
| Принят по гарантии | Новый, тип «Гарантийный возврат» |

Незнакомый статус не выдумывается: колонка остаётся пустой, заказ встанет на
начальный статус, а в отчёте будет сказано, сколько таких и какие.

**Склад** — из таблицы `Stock`. Цена там одна, продажная; кладём её в
себестоимость, потому что другого места нет. Проверьте после загрузки.

**Услуг в старой программе нет.** Прайса как таблицы там не существует:
выполненные работы записывались в заказ свободным текстом. В присланной базе
3384 разных текста, и повторяются из них ровно двенадцать — прайс из этого не
собрать, а выдуманный прайс хуже отсутствующего. Заводится руками в
Настройки → Услуги, либо загружается своим файлом.

## Клиенты, которых в файлах нет

Заказ ссылается на клиента номером, а сама карточка может остаться в базе,
которую вам не отдали: так бывает, когда выгрузку заказов делали отдельно от
базы клиентов. Раньше такой заказ было некуда девать — телефон был
единственным ключом, и без него заказ оставался ничей.

Теперь заказ держится за номер. Клиент, которого нет в файлах, заводится
карточкой «Клиент №1463 (из старой базы)» — без имени и телефона, но с
номером. Найдётся рабочая база — положите её в ту же папку, запустите утилиту
снова и загрузите файл клиентов: карточки допишутся именами и телефонами, а
заказы останутся на своих местах. Ничего не задвоится, потому что сличаем по
номеру.

Телефон-заглушку вроде `00000000000` в базу не тащим: это не номер, а «клиент
номер не дал», и одна карточка собрала бы их всех. Сам клиент при этом
переносится — у него есть номер и имя.

## Что не переносится совсем

- Заказы, помеченные удалёнными в старой программе.
- Заказы, в которых не указан клиент вовсе, — они складываются в
  `ne-pereneseno.csv` с причиной.
- Фотографии, журнал действий и история смены статусов.

## Несколько снимков сразу

Снимков можно положить сколько угодно. Утилита сливает их по номеру заказа,
и при расхождении побеждает более свежий; свежесть определяется по самой
поздней дате приёма в файле. Пустое поле свежего снимка не затирает
заполненное в старом.

Именно так разобрался обычный случай «есть архивная выгрузка за три года и
есть рабочая база за последний год».

## Как это устроено

```
perenos.js     чтение источников, слияние, запись файлов
sqlite.js      чтение таблиц из .sqlite без зависимостей
test.js        проверка
proba.sqlite   маленькая база-образец для проверки
perenos.bat    запуск двойным щелчком в Windows
```

Зависимостей нет ни одной, и это осознанно. Утилита запускается один раз в
чужой мастерской, где может не быть ни интернета, ни прав ставить пакеты;
драйвер sqlite — нативный модуль, и первое же «не удалось собрать» превращает
пятиминутный перенос в переписку на два дня. Поэтому чтение файла sqlite
написано своими руками: обход дерева таблицы, разбор записи и страницы
переполнения — больше ничего и не нужно.

Читалка сверена с настоящим sqlite на живой базе: девять таблиц, 14 985
строк, включая длинные комментарии, уезжающие в страницы переполнения, —
расхождений нет.

**Выгрузка в csv читается по порядку колонок, а не по заголовкам.** В
присланной выгрузке шапка подписана руками и с середины съезжает: под
«Итого» лежит скидка, под «Скидка» — фамилия мастера, под «Статус» —
«30 дней». Excel о таком не предупреждает, и файл, прочитанный по
заголовкам, выглядит правдоподобно и весь неверен. Порядок колонок у
выгрузки тот же, что у таблицы в базе, — на него и опираемся.

## Проверка

```
node test.js
```

Гоняет на `proba.sqlite` — маленькой базе, собранной из настоящих граблей:
съехавшая шапка, «0» в колонке-галочке, телефон-заглушка, двойник по
телефону, дефис вместо пустого поля, комментарий в страницах переполнения.

База-образец лежит в репозитории готовой нарочно: иначе проверка требовала бы
установленного `sqlite3`. Пересобрать её можно так (нужен `sqlite3` и
`python3`) — файл `proba.sql` рядом хранит те же данные текстом:

```
rm proba.sqlite && sqlite3 proba.sqlite < proba.sql
```
