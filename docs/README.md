# Заметки по разработке

Сюда складываем решения, которые приняли по ходу: почему сделали так, а не иначе.
Основной документ по архитектуре живёт в проекте Claude «RepairShop» (`architecture.md`).

## Что сделано

- Каркас проекта, схема данных (28 моделей), политики RLS, роли-пресеты.
- Аутентификация: единый вход по email для всех ролей, refresh в httpOnly-куке
  с ротацией и обнаружением повторного использования, ограничение попыток входа.
- Панель платформы: список мастерских со счётчиками, создание мастерской под ключ,
  статусы подписки, администраторы, журнал действий, режим «войти как» с записью в журнал.
- Сотрудники и роли внутри мастерской, правило «нельзя выдать право, которого нет у себя»,
  лимит сотрудников по тарифу, мягкое удаление, отзыв сессий при смене пароля и отключении.
- Фронтенд: вход, панель мастерских, экран сотрудников, макет с боковым меню и нижней навигацией.

## Решения, которые стоит помнить

- **Вход один на всех, по email.** Ни выбора «мастерская или платформа», ни отдельного поля с кодом
  мастерской. Плата за это — email уникален по всей платформе: две мастерские не могут завести
  сотрудника с одним адресом. Для сотрудников без почты договорились об адресах вида
  `имя@<код мастерской>.local`.
- **Поиск по email снимает изоляцию ровно на один запрос** (`locateTenantUser`), возвращающий
  только `id` и `tenantId`. Всё остальное — уже внутри `withTenant`.

- **Приложение ходит в базу под отдельной ролью.** Суперпользователь PostgreSQL игнорирует RLS
  всегда — под ним изоляция мастерских не работает вообще. Миграции идут под владельцем,
  рантайм — под `APP_DB_USER`.
- **Режим платформы (`app.platform = 'on'`)** снимает изоляцию внутри одной транзакции.
  Нужен только для сводных цифр в панели собственника, используется в одном месте — `withPlatform()`.
- **`findUnique` для таблиц мастерской запрещён:** в него нельзя подмешать `tenantId`.
  Прокси в `withTenant` бросает понятную ошибку и предлагает `findFirst`.
- **Вложенные `create`** прокси не покрывает — дочерние записи вставляйте отдельными вызовами,
  иначе их отклонит RLS.

- **Заявка не создаёт мастерскую.** До одобрения существует только строка в `TenantApplication`.
  Так открытая форма регистрации не даёт боту ничего ценного, а отклонённая заявка не оставляет мусора.
- **Пароль заявителя переносится хешем.** В открытом виде его нет ни в какой момент, и человек
  входит тем же паролем, который придумал при регистрации.
- **Статус заявки раскрывается только знающему пароль от неё** — иначе форма входа стала бы
  способом узнать, кто обращался за подключением.
