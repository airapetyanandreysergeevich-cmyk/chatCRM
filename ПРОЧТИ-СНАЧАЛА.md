# Приём заказа — что делать с этим архивом

Связь с твоим компьютером пропала, поэтому файлы приезжают архивом.
Распаковать **поверх** `D:\CRM\repairshop` — структура папок уже совпадает,
ничего лишнего архив не содержит.

Новых полей в базе нет — **миграция не нужна**. Всё, что понадобилось
(комплектность, внешнее состояние, место хранения, согласованная сумма,
гарантия, ссылка на прошлый заказ), уже было в схеме.

## 1. Зависимости бэкенда

Появились три новые библиотеки. Проверь, есть ли они уже:

```
cd D:\CRM\repairshop\backend
findstr /C:"multer" /C:"@aws-sdk" package.json
```

Если строк нет — добавь:

```
npm i multer @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
npm i -D @types/multer
```

(если node на Windows не стоит — скажи, сделаем это на сервере)

## 2. Отправить в git

```
cd D:\CRM\repairshop
git add -A
git commit -m "Приём заказа: бланк, фотографии, работы и запчасти, выдача"
git push
```

## 3. На сервере

```
cd /root/repairshop
git pull
docker compose --env-file deploy/.env up -d --build
docker compose --env-file deploy/.env logs -f backend
```

В логе при старте должно быть тихо. Если увидишь
«Не удалось подготовить хранилище файлов» — не поднялся MinIO,
фотографии грузиться не будут, остальное работает.

## 4. Проверить руками

1. Войти приёмщиком → «Заказы» → «Принять технику».
2. Ввести телефон клиента — если он уже был, имя и адрес подставятся сами.
3. Заполнить бланк, отметить комплектность, сохранить.
4. Открыть заказ → добавить фото → добавить работы и запчасти → «Ремонт готов».
5. Зайти мастером и убедиться, что телефона клиента и денег он **не видит**.

## 5. Осталось с прошлого раза

```
bash deploy/setup-https.sh www.finecrm.ru
```

и после того как заработает — в `deploy/.env` сменить
`CORS_ORIGIN=*` на `CORS_ORIGIN=https://www.finecrm.ru`.
