# Оповещения, PWA и приложение для Android

Распаковать **поверх** `D:\CRM\repairshop`. Архив включает и прошлую посылку
(приём заказа) — если ты её ещё не применял, отдельно ничего искать не надо.

**Главное: без https не заработает ничего из этого.** Не моя прихоть —
браузеры не запускают service worker на `http://`, а без него нет ни push, ни
установки на телефон, ни APK без адресной строки. Поэтому первым делом:

```
bash deploy/setup-https.sh www.finecrm.ru
```

---

## 1. Зависимости бэкенда

```
cd D:\CRM\repairshop\backend
findstr /C:"web-push" /C:"multer" /C:"@aws-sdk" package.json
```

Чего нет — доставить:

```
npm i web-push multer @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
npm i -D @types/web-push @types/multer
```

## 2. Не пускать в git ключ подписи

Добавь в `.gitignore`:

```
deploy/android/android.keystore
deploy/android/*.apk
deploy/android/app/
deploy/android/.gradle/
```

Ключ подписи в репозитории — это возможность для любого, кто его увидит,
собрать «обновление» твоего приложения. И наоборот: потеряешь файл — обновить
уже установленное будет нечем, всем придётся сносить и ставить заново.
Держи копию отдельно от сервера.

## 3. Отправить в git

```
cd D:\CRM\repairshop
git add -A
git commit -m "Оповещения: Web Push, настройки по ролям, PWA и APK для Android"
git push
```

## 4. На сервере

```
cd /root/repairshop
git pull

# ключи оповещений — один раз и навсегда
bash deploy/vapid-init.sh

# в схеме поменялась одна таблица: у подписки на оповещения
# теперь может не быть мастерской (это ты как собственник платформы)
bash deploy/db-new-migration.sh push_subscription_platform

docker compose --env-file deploy/.env up -d --build
docker compose --env-file deploy/.env logs -f backend
```

В логе при старте не должно быть строки «Оповещения выключены». Если она есть —
`vapid-init.sh` не отработал или бэкенд не перечитал `.env`.

## 5. Проверить

1. Открыть сайт по https, войти.
2. «Оповещения» → «Включить оповещения» → «Проверить». Должно прийти.
3. Владельцу мастерской там же настроить, кому какие события уходят.
4. Назначить мастеру заказ и убедиться, что ему пришло, а тебе — нет
   (себе оповещения о собственных действиях не приходят).

## 6. Приложение для Android

```
bash deploy/build-apk.sh
```

Первый запуск долгий: качается Android SDK, около гигабайта. Дальше — минуты.
Скрипт сам создаст ключ подписи, положит `assetlinks.json` во фронтенд и
соберёт подписанный APK.

После сборки — пересобрать фронтенд, чтобы `assetlinks.json` попал на сайт:

```
docker compose --env-file deploy/.env up -d --build frontend
```

Забрать файл: `scp root@147.45.249.114:/root/repairshop/deploy/android/app-release-signed.apk .`

При установке Android один раз спросит разрешение ставить из неизвестного
источника — это нормально для APK не из Play.

## 7. iPhone

Отдельного приложения нет и не будет: Apple не пускает в App Store обёртки
вокруг сайта. Но результат для сотрудника тот же — Safari → «Поделиться» →
«На экран „Домой“». Иконка на экране, полноэкранный режим без адресной строки,
оповещения работают. Экран «Оповещения» сам покажет эту инструкцию, когда
поймёт, что открыт на iPhone во вкладке, а не с домашнего экрана.

Единственное отличие от Android: пока приложение не добавлено на «Домой»,
оповещения не приходят вообще. Это ограничение iOS, обойти его нечем.
